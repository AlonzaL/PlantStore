# 🌿 PlantStore - Android App

Современное Android-приложение (e-commerce) для продажи комнатных и декоративных растений. Написано на **Kotlin** с использованием **Jetpack Compose**. Архитектура приложения следует принципам Clean Architecture и MVVM. В качестве бэкенда используется **Firebase** (Authentication & Firestore).

## 📱 Скриншоты

Визуальная часть приложения и пользовательский опыт основаны на публичном UI-ките **"Kimi - Free Plant Store Mobile UI Kit"** от Pixelbites. Это позволило сосредоточиться на технической реализации и переносе качественного дизайна в код на Jetpack Compose.

## 🚀 Технологический стек

*   **Язык:** Kotlin
*   **UI:** [Jetpack Compose](https://developer.android.com/jetpack/compose) (Material3)
*   **Архитектура:** MVVM (Model-View-ViewModel) + Repository Pattern
*   **Асинхронность:** Coroutines & Kotlin Flow
*   **Навигация:** Jetpack Navigation Compose
*   **Бэкенд (Firebase):**
    *   **Authentication:** Регистрация и вход по Email/Паролю.
    *   **Firestore Database:** NoSQL база данных для хранения товаров и пользовательских данных.
*   **Загрузка изображений:** [Coil](https://coil-kt.github.io/coil/)

## ✨ Ключевые функции

*   **Система авторизации:**
    *   Регистрация (Sign Up) и Вход (Log In).
    *   Безопасный выход из системы.
    *   **Удаление аккаунта:** Полное удаление данных пользователя из базы и системы аутентификации (с проверкой безопасности).
*   **Каталог товаров:**
    *   Главный экран с категориями "Популярное" и "Новое".
    *   Горизонтальные списки и адаптивные сетки (Grid).
    *   **Pixel-perfect** верстка в соответствии с дизайном.
*   **Система "Избранное":**
    *   **Персонализация:** Лайки хранятся в коллекции пользователя `users/{uid}/favorites`, а не в товаре.
    *   **Optimistic Updates:** Мгновенное обновление иконки лайка до ответа сервера.
    *   **Синхронизация:** Состояние лайка синхронизируется между Главным экраном, Деталями и Профилем в реальном времени.
*   **Профиль пользователя:**
    *   Отображение имени и Email.
    *   Превью избранных товаров.
    *   UI-заготовка для корзины заказов.

## 🔥 Бэкенд и Структура Данных (Firebase)

Приложение использует **Cloud Firestore** с разделением данных на общедоступные и приватные. Это обеспечивает безопасность и персонализацию.

### Схема Базы Данных (NoSQL)

1.  **`plants` (Коллекция)** — Глобальный каталог товаров.
    *   Доступ: `read: public`, `write: admin only`.
    *   Содержит информацию о растениях (название, цена, картинки, категории).
    *   *Особенность:* Поля `isFavorite` внутри товара игнорируются или отсутствуют. Лайки вычисляются на клиенте.

2.  **`users` (Коллекция)** — Приватные данные пользователей.
    *   Доступ: Только владелец аккаунта (`request.auth.uid == userId`).
    *   **Документ пользователя:** Хранит профиль (Email, Name).
    *   **Sub-collections:**
        *   `favorites`: Хранит ID лайкнутых товаров.
        *   `cart`: (В разработке) Хранит товары корзины.

### Логика работы "Избранного"

Реализован принцип **Single Source of Truth**:
1.  `Repository` загружает список всех растений из `plants`.
2.  Параллельно загружается список ID лайков из `users/{uid}/favorites`.
3.  `ViewModel` объединяет эти данные (Merge), проставляя флаг `isFavorite = true` локально.
4.  Это позволяет разным пользователям иметь разные списки избранного для одних и тех же товаров.

## 📂 Архитектура и Структура Проекта

Проект организован по пакетам в соответствии с их функциональной ответственностью (Feature-based + Layer-based):

```text
com.example.plantstore.plantstore
├── domain/                 # Сущности (Data Classes)
│   ├── PlantModel.kt       # Модель товара (с поддержкой Firestore парсинга)
│   └── UserModel.kt        # Модель профиля пользователя
│
├── repository/             # Слой данных (Data Layer)
│   ├── AuthRepository.kt   # Взаимодействие с Firebase Auth и коллекцией users
│   └── MainRepository.kt   # Загрузка товаров и синхронизация избранного
│
├── viewModel/              # Слой бизнес-логики (State Holders)
│   ├── AuthViewModel.kt    # Логика входа, регистрации и управления состоянием Auth
│   └── MainViewModel.kt    # Логика главной страницы, фильтрация и обработка лайков
│
├── screen/                 # Слой UI (Jetpack Compose Screens)
│   ├── auth/               # Экраны авторизации (Login, SignUp)
│   ├── main/               # Главный экран (Home) с категориями
│   ├── detail/             # Экран деталей товара
│   ├── settings/           # Экран профиля пользователя
│   ├── listPlant/          # Экран полного списка товаров (Grid)
│   └── intro/              # Welcome экран
│
├── navigation/             # Навигация
│   ├── NavGraph.kt         # Граф навигации и композиция экранов
│   └── Screen.kt           # Sealed class для маршрутов (Routes)
│
└── components/             # Переиспользуемые UI элементы
    ├── PlantCard.kt        # Карточка товара
    ├── TopBars.kt          # Универсальные верхние панели
    └── ...
```
